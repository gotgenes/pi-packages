### K7: what a bash ask names, and what its session grant covers (new)

Carrier: #1095.
Members: #1101, #1063, #1065, PR #1097.

The mechanism, confirmed in source:

- `pickMostRestrictive` breaks a tie toward the first unit (`src/policy/restrictiveness.ts`, "first-wins on ties"), so `cd sub && npm test` under `bash: {"*": "ask"}` asks about `cd sub`.
- The session option is suggested from that one unit, and `bash-arity.ts` has no `cd` entry, so it reads `cd *`.
- `withAskingUnits` (`src/handlers/gates/bash-command.ts:131`) already carries every still-asking unit on the chosen one, but only the forwarding path reads it.
- `AuthorizerVerdict` has three shapes (`allow`, `deny`, `defer`), so a chain link that accepts part of a call can only defer; #1101 is that case, where the dialog names the assignment a link accepted while the grant approves `git commit`.

The decision is presentation and grant scope together: one prompt naming every asking unit, or one prompt per unit (PR #1097's choice), and whether the chain gains a partial verdict (#1095's `allow_units`).
Both touch ADR 0011 (what a prompt must show) and ADR 0007 (what a link may return).
#1063 and #1065 are the pattern-breadth half of the same grant, in the same `pattern-suggest.ts`.
PR #1097 is green and current; review it against the decision, not before it.
